# psd-paint

선화 PSD에 밑색 레이어를 자동으로 깔아 준다. 작가가 PSD 안에 `참고` 폴더를 만들고 영역마다 점이나 낙서로 힌트를 칠하면, 선화로 닫힌 영역을 힌트 색으로 채워 부위별 레이어(`머리`, `피부`, `재킷` …)로 나눠 저장한다.

> 설치·앱 사용·MCP 연결은 [GUIDE.md](GUIDE.md)를 보세요.

## 참고 방식

앱에서 고르는 방식은 **파일 안 참고 레이어**와 **캐릭터 프리셋 · AI** 두 가지다.
레퍼런스 이미지·PSD(다른 페이지를 AI 번호 매칭으로 칠하기)는 결과가 나쁘고 요청만 많아 앱에서 뺐다.
엔진·CLI(`--ref-image`, `--ref-psd`)·MCP(`reference`)에는 아직 남아 있다.

| 방식 | 넣는 것 | 레이어 이름 |
|---|---|---|
| 파일 안 참고 레이어 | PSD 안의 `참고` 폴더(점·낙서 힌트) 또는 칠해 둔 `참고` 레이어 하나 | 폴더면 하위 레이어 이름, 레이어 하나면 `색_RRGGBB` |
| 레퍼런스 이미지 | 같은 페이지를 칠한 PNG·JPG | `색_RRGGBB` |
| 레퍼런스 PSD | 같은 페이지에 밑색이 칠해진 PSD (`밑색` 또는 `참고` 폴더) | 레퍼런스 PSD의 레이어 이름 그대로 |
| 캐릭터 프리셋 | 색상 프리셋 `캐릭터/부위`(예: `하늘/머리`) + 캐릭터 생김새 한 줄 | 부위마다 하나 (머리·피부·겉옷 …), 색은 캐릭터마다 |

- 같은 페이지를 칠한 레퍼런스면 AI 없이 바로 칠한다. 다른 페이지면 아래 AI 매칭을 쓴다.
- 칠한 예시(레이어 하나, 이미지, 밑색 없는 레퍼런스 PSD)는 브러시 결·안티에일리어싱으로 생긴 비슷한 색을 대표색으로 묶는다. 영역의 30% 이상을 덮은 색만 쓰고, 흰색으로 칠해진 배경은 비운다.
- 파일 안 참고 레이어 방식에서 `참고`가 없으면 PSD 옆 `파일이름_참고.png`를 찾는다.

### 캐릭터 프리셋 방식
색은 색상 프리셋 `캐릭터/부위`에서, 누구인지는 캐릭터 프로필(대표 그림·생김새, 캐릭터 탭)로 알아본다. 부위 나누기는 둘 중 하나(`parts_method`).

**영역 확인 칸 (`tiles`, 기본 — 글 AI만으로)**
1. 넓이 `tile_min_area`(기본 1000px) 이상인 영역을 페이지 위→아래 순서로 칸에 담는다. 칸마다 둘레를 넉넉히 잘라 그 영역만 빨갛게 칠한다 (5×4 판).
   - 컷마다 가장 넓고 컷의 네 변에 모두 닿은 영역(컷 배경)과 컷 바깥 여백은 묻지 않고 배경으로 둔다 (`tile_auto_bg`).
   - 원고 3장 기준으로 칸이 22~27% 줄었다 (121→89, 166→130, 98→72).
2. 글 AI(Claude 등)가 등장인물 대표 그림과 칸을 보고 칸마다 `part`(부위·사물·배경)와 `character`(이름·모름·없음)를 답한다.
   - 칸을 만들기 전에 컷 배경으로 보이는 큰 영역(`leak_min_area` 2만px 이상) 안에서만, 선 끝을 그 방향 `bridge_px`(40px) 안의 선까지
     곧은 선으로 이어 다시 나눈다. 옆얼굴처럼 선이 크게 열려 얼굴과 컷 배경이 한 영역일 때 얼굴을 떼어 낸다.
     사람 안쪽(머리카락 결 등)은 잇지 않아 칸이 거의 늘지 않는다 (원고 3장: 1~7칸). 잇는 선 자리는 밑색으로 칠한다.
3. 배경이라고 한 영역만 비우고, 칸에 담지 않은 작은 영역(머리카락·피부 경계의 좁은 틈 등)은 둘레를 따른다.
4. 답의 '누구인지'를 바로잡는다: 맞닿은 같은 이름 영역을 뭉치로 묶고, 뭉치의 바깥 이웃 80% 이상이 한 사람이며
   그 사람 쪽 뭉치 넓이의 20%보다 작은 뭉치는 그 사람으로 바꾼다 (몸 안에 박힌 작은 실수만 고치고, 두 사람의 경계는 건드리지 않는다).
- 다 칠하면 한 번 검수한다: 칠한 결과 위에 칸 번호를 얹은 지도(`check_*.png`, 컷 단위)를 보여 주고,
  틀린 칸만 `apply_characters(items, checked=true)`로 다시 받는다. 큰 조각을 통째로 잘못 답한 것(재킷을 옆 사람 셔츠로 등)은 자동 보정으로 못 고쳐서 이 단계가 잡는다.
- MCP는 판(칸 20개)을 한 장씩 준다. `apply_characters(items)`로 그 판을 답하면 다음 판을 주고, 다 모이면 칠한다 (`partial.json`에 모은다).
   큰 덩어리(머리·피부·겉옷·안옷·하의·신발)는 정확히 나누고, 좁은 경계는 조금 뭉쳐져도 실루엣 안은 빈틈없이 칠하는 것이 목표다.

**이미지 지도 (`image`, Gemini 키 필요)**
1. 페이지를 컷 단위로 나눠(컷 중간은 자르지 않는다), Gemini 이미지 모델(기본 `gemini-3.1-flash-lite-image`)이 컷마다 세 번 칠한다: 부위별 코드 색 2장, 사람별 코드 색 1장. 부위 지도는 두 장이 같은 픽셀만 믿는다.
2. 영역마다 칠해진 색을 다수결해 부위·사람을 정한다. 선이 끊겨 한 영역에 부위가 섞이면 지도 경계대로 나눈다.
   - 사람 실루엣 안은 빈틈없이 칠한다. 실루엣 안인데 두 지도가 배경이라고 한 곳(가닥 사이 틈)은 가장 가까운 몸 부위로 채운다.
   - 실루엣 밖이고 지도가 배경이라고 한 영역만 비운다 (자동 회색 칠하기도 하지 않는다).
   - 몸이 거의 없는 '사람'(컷 테두리에 칠한 것 등)은 버린다.
3. 사람마다 잘라 낸 선화를 글 AI가 보고 누구인지 고른다.

- 프리셋에 없는 인물·부위는 부위별 회색, 피부는 캐릭터들이 가장 많이 쓴 피부색이다.
- 등록하지 않은 인물(모름)은 `밑색/엑스트라` 폴더의 머리·피부·옷·기타 네 레이어로 칠한다 (`extra_group`, 앱 설정 '엑스트라'). 레이어 상한 셈에서 뺀다.
- 등록한 캐릭터라도 그 옷 부위 색이 없으면 가까운 등록 부위를 쓴다 (겉옷 → 상의 → 셔츠, 하의 ↔ 치마). AI에게도 캐릭터마다 등록한 옷을 알려 준다.
- 컷 테두리는 네 변 중 대부분이 곧은 변만 끝까지 이어 그려 경계로 쓴다 (머리카락이 테두리를 넘으며 지운 자리로 얼굴이 페이지 여백과 이어지지 않게).
- 부위 말: 머리(머리카락)·피부·머리띠(모자)·재킷(겉옷·코트)·조끼(니트·스웨터·상의)·셔츠·넥타이(리본)·바지(하의)·치마·신발·양말·소품.
- 프로필은 앱 데이터 폴더(`~/Library/Application Support/psd-paint/characters.json`, 그림은 `characters/`)에 저장한다. MCP 서버도 여기서 읽는다.
- 요청·답은 `원본_밑색_AI매칭/`에 남는다 (`tiles_*`, `profile_*` 또는 `parts_*`, `persons_*`, `person_*`).
- CLI: `--characters` (앱에 저장한 프리셋·프로필을 읽는다), `--parts tiles|image`, `--image-model`.

## 참고 레이어 규칙 (점·낙서 힌트)

```
참고 (폴더)
 ├ 머리    ← 머리 영역마다 점 하나 또는 낙서
 ├ 피부
 ├ 재킷
 └ …
```

- 하위 레이어 이름이 결과의 밑색 레이어 이름이 된다.
- 칠한 색이 그 영역의 밑색이 된다. 같은 레이어 안에서 인물마다 다른 색을 써도 된다.
- 영역 안에 점 하나만 찍어도 영역 전체가 칠해진다. 한 영역에 힌트가 여럿이면 가장 많이 칠한 색을 쓴다.
- 힌트가 없는 작은 영역(400px 미만)은 가장 많이 맞닿은 이웃 영역을 따른다.
- 흰색 힌트도 그대로 흰색으로 칠한다 (흰 셔츠 등).
- `참고`를 폴더가 아닌 레이어 하나로 두면 색마다 `색_RRGGBB` 레이어로 나뉜다.
- 결과 PSD에서는 `참고` 폴더를 숨긴다.

## 힌트 없는 영역 자동 칠하기

`참고` 폴더가 없거나 힌트를 찍지 않은 영역(엑스트라 등)은 회색으로 자동 칠해 `자동` 레이어에 넣는다. 영역 구분만 되어 있으면 색은 나중에 바꾸기 쉽기 때문이다.

- 맞닿은 영역끼리는 다른 회색을 고른다.
- 배경은 칠하지 않는다. 컷마다 가장 큰 영역, 그리고 둘레 대부분이 컷 테두리에 닿은 영역(컷 구석)을 배경으로 본다.
- 끄려면 앱 설정에서 체크를 풀거나 CLI에 `--no-auto`를 준다. 끄면 `참고` 폴더가 없는 파일은 실패로 건너뛴다.

## 배경

- 이름이 `배경*`, `*background*`, `BG*`, `bg*`에 맞는 레이어·폴더는 배경으로 본다.
- 선화 폴더 안에 배경 선이 있어도 경계에서 빼서 배경이 잘게 쪼개지지 않게 한다.
- 결과 PSD에서는 배경을 끈다.

## 레이어 수 상한

밑색 레이어가 `--max-layers`(기본 10)를 넘으면 칠한 면적이 작은 레이어부터 `기타` 레이어로 합친다. 합쳐도 영역마다 원래 색은 그대로다. `0`이면 제한하지 않는다.

## AI 매칭 (다른 페이지 레퍼런스)

레퍼런스 이미지·PSD가 원고와 다른 페이지(캐릭터 시트, 앞 회차의 채색 페이지 등)면 AI가 인물과 부위를 맞춰 칠한다. 레퍼런스 선이 원고 선화와 40% 미만으로 겹치거나, 크기가 다르거나, 레퍼런스 PSD에 선화 폴더가 없으면 다른 페이지로 본다.

1. 원고를 영역으로 나누고 칠할 영역마다 번호를 붙인 지도 이미지를 만든다.
2. 레퍼런스에서 색 팔레트(P1, P2 …)를 뽑아 표시를 얹는다. 레퍼런스 PSD에 `밑색` 폴더가 있으면 그 레이어 이름을 쓴다.
3. AI가 번호마다 팔레트를 고르고, 고르지 못한 영역은 `자동` 회색으로 칠한다.

- API 방식은 기본으로 **검수**를 한 번 더 한다. 칠한 결과 지도(번호 + 칠한 색)를 레퍼런스와 함께 다시 보여 주고 틀린 번호만 고친다. 요청이 1회 늘어나며 `--no-review`로 끈다.
- 요청·답·칠한 결과 지도는 `원본_밑색_AI매칭/` 폴더에 남는다. `answer.json`을 고쳐 '요청 폴더' 방식으로 다시 실행하면 고친 답으로 칠한다.
- 로그에 토큰 수와 예상 비용을 적는다. 비용은 단가를 등록한 모델(`ai.PRICES`, 지금은 Claude)만 계산한다.

AI에 묻는 방법은 두 가지다.

| 방식 | 필요한 것 | 흐름 |
|---|---|---|
| API로 바로 매칭 | Claude·OpenAI·Gemini 중 하나의 API 키 (구독과 별도 과금) | 실행하면 바로 칠한다 |
| 요청 폴더 만들기 | Claude Code·Codex 등 구독 도구 | `원본_밑색_AI매칭/` 폴더가 생긴다 → 도구에서 README.md대로 `answer.json`을 만든다 → 같은 파일을 다시 실행하면 적용한다 |

```bash
.venv/bin/python -m psdpaint 1화_2.psd --ref-psd 1화_3_밑색.psd --ai files
```

## MCP 서버 (구독으로 AI 매칭)

앱 설정의 **칠하는 곳**에서 Claude 데스크톱·Codex(ChatGPT 앱)·Gemini CLI를 고르면, [연결하기]가 각 앱 설정에 psd-paint를 등록하고
(`claude_desktop_config.json`, `~/.codex/config.toml`, `~/.gemini/settings.json`, 원래 파일은 `.bak`으로 남긴다),
[밑색 칠하기]가 칠할 파일이 적힌 요청을 넣어 그 앱을 연다 (Claude는 Code 탭 `claude://code/new?q=…&folder=…`, `codex://new?prompt=…&path=…`, 터미널에서 `gemini -i …`).
요청은 입력창에 들어가기만 하고 보내지는 않는다. 코드는 `psdpaint/clients.py`.

Claude 데스크톱·Claude Code에 psd-paint를 커넥터로 붙이면 API 키 없이 쓸 수 있다. 다른 페이지 레퍼런스는 클라이언트의 AI가 지도 이미지를 보고 직접 영역을 맞춘다.

| 도구 | 하는 일 |
|---|---|
| `inspect_psd` | 레이어 구조(폴더·레이어 이름, 숨김 여부)를 보여 준다 |
| `paint_psd` | 밑색을 칠해 `원본이름_밑색.psd`로 저장하고 미리보기를 돌려준다. 다른 페이지 레퍼런스면 레퍼런스·번호 지도 이미지를 돌려준다 |
| `apply_match` | AI가 고른 영역별 팔레트를 적용해 칠한다 |
| `paint_characters` | 앱에 등록한 캐릭터로 칠한다 (`paint_psd(characters=true)`와 같다). 등장인물 그림과 영역 확인 칸을 돌려준다 |
| `apply_characters` | `paint_psd(characters=true)`의 요청에 답한다: 영역 확인 칸이면 `items`(칸마다 부위·누구인지, 고칠 칸만 다시 보내도 된다), 이미지 지도면 `people` |

예: "이 PSD를 1화_3_밑색.psd 레퍼런스로 칠해 줘" → `paint_psd` → (AI가 이미지를 보고) `apply_match` → 완료

### 등록

Claude Code:

```bash
claude mcp add psd-paint -e PYTHONPATH=/절대경로/psd-paint -- /절대경로/psd-paint/.venv/bin/python -m psdpaint.mcp_server
```

Claude 데스크톱 (`~/Library/Application Support/Claude/claude_desktop_config.json`):

```json
{
  "mcpServers": {
    "psd-paint": {
      "command": "/절대경로/psd-paint/.venv/bin/python",
      "args": ["-m", "psdpaint.mcp_server"],
      "env": {"PYTHONPATH": "/절대경로/psd-paint"}
    }
  }
}
```

## AI 연결 (선택)

앱 설정에서 제공자(Claude · OpenAI(Codex) · Gemini), 모델, API 키를 넣고 [연결 테스트]로 확인한다. 모델은 목록에서 고르거나 직접 입력하고, [목록 불러오기]로 키에서 쓸 수 있는 모델 이름을 받아 온다. 키는 OS 자격 증명 저장소(macOS 키체인, Windows 자격 증명 관리자)에 저장한다. 연결 테스트는 모델 정보만 조회해 토큰을 쓰지 않는다. AI 매칭의 'API로 바로 매칭'에 쓴다.

## 결과

- `선화` 폴더 바로 아래에 `밑색` 폴더를 만들고, `참고` 폴더와 같은 순서로 레이어를 넣는다.
- 레이어는 마스크 없는 일반 픽셀 레이어다.
- 원본은 건드리지 않고 `원본이름_밑색.psd`로 저장한다. `--overwrite`(앱: 원본에 덮어쓰기)면 원본에 저장하고, 처음 한 번 `원본이름_백업.psd`를 남긴다.
- 이미 밑색 폴더가 있는 파일을 다시 칠하면 그 폴더를 새것으로 바꾼다. 저장은 임시 파일에 쓴 뒤 바꿔 넣는다.

## 사용법

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

### 앱 (GUI)

```bash
.venv/bin/python -m psdpaint.gui
```

- PSD 파일이나 폴더를 창에 끌어 놓거나 [파일 추가…]로 고른다. 같은 파일은 한 번만 들어간다.
- [▶ 밑색 칠하기]를 누르면 순서대로 처리한다. 파일마다 진행률과 결과를 보여 주고, 실패한 파일은 건너뛴다.
- [중지]는 지금 처리 중인 파일을 마친 뒤 멈춘다.
- 완료한 파일을 고르면 오른쪽에 미리보기가 나온다. [파일 열기]는 연결된 앱(예: 클립스튜디오)으로 열고, [폴더에서 보기]는 Finder·탐색기에서 위치를 보여 준다.
- 설정은 다음 실행 때도 유지된다.
- **파일별 실행**: 파일 목록 우클릭 → 선택한 파일만 칠하기, 파일마다 레퍼런스 지정·해제.
- **클릭 수정**: 미리보기에서 영역을 누르면 레이어·색을 고르는 메뉴가 뜬다. 고친 뒤 [수정 저장]을 누르면 AI를 부르지 않고 PSD를 다시 저장한다.
- **연속 모드**: 레퍼런스 이미지·PSD 방식으로 여러 파일을 처리하면 앞 파일 결과가 다음 파일의 레퍼런스가 된다 (CLI도 같다).

### 명령줄 (CLI)

```bash
# 여러 파일을 순서대로 처리한다. 실패한 파일은 건너뛰고 계속한다.
.venv/bin/python -m psdpaint 1화.psd 2화.psd 3화.psd -o 결과폴더
```

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `-o`, `--out` | 원본과 같은 폴더 | 결과 폴더 |
| `--suffix` | `_밑색` | 결과 파일 이름 뒤에 붙일 말 |
| `--overwrite` | 끔 | 원본에 덮어쓴다 (처음 한 번 `_백업.psd`를 남긴다) |
| `--line` | `선화` | 선화 레이어가 든 폴더 이름 |
| `--hint` | `참고` | 힌트 폴더 이름 |
| `--offset` | `2` | 밑색 바깥 윤곽을 안쪽으로 줄이는 px |
| `--gap` | `2` | 끊긴 선의 틈을 막는 정도(px) |
| `--max-layers` | `10` | 밑색 레이어 수 상한 (`0` = 제한 없음) |
| `--no-auto` | | 힌트 없는 영역을 자동으로 칠하지 않는다 |
| `--boundary` | `컷*`, `*테두리*` | 선화 외에 경계로 쓸 레이어 이름 패턴. 여러 번 지정할 수 있다 |

컷 테두리는 `--boundary` 패턴에 맞는 보이는 픽셀 레이어로 찾는다. 숨긴 레이어와 캔버스 절반 이상을 덮는 레이어(컷 배경 등)는 경계에서 뺀다.

## 처리 순서

1. 선화와 컷 테두리를 합쳐 경계를 만들고, 끊긴 선을 `--gap`만큼 두껍게 해 닫힌 영역으로 나눈다.
2. 영역마다 `참고` 힌트를 대응한다.
3. 선 아래까지 밑색을 넓힌다.
4. `머리` 레이어는 잔머리 가닥 사이 작은 틈을 채운다.
5. 밑색 바깥 윤곽을 `--offset`만큼 안쪽으로 줄인다.

## 버전과 릴리스

- 버전은 `psdpaint/__init__.py`의 `__version__`에 적는다 (예: `0.1.0`). 앱 제목줄에 표시된다.
- 릴리스: 버전을 올려 커밋한 뒤 같은 번호의 태그를 푸시한다. GitHub Actions(`.github/workflows/release.yml`)가 Mac(Apple Silicon)·Windows 설치 파일을 만들어 Releases에 올린다. 태그와 앱 버전이 다르면 빌드를 멈춘다.

```bash
git tag v0.1.0 && git push origin v0.1.0
```

- 평소 코드 푸시로는 빌드하지 않는다. Actions 탭에서 손으로 실행하면 설치 파일만 만들어 보관한다(릴리스 없음).
- 로컬 빌드: `.venv/bin/pip install pyinstaller && .venv/bin/python build.py` → `dist/`
- 설치 앱 실행 옵션: 인자 없이 = 앱 창, `--mcp` = MCP 서버, `--version` = 버전 출력
